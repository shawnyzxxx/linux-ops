# RHCSE 第三节：时间时钟与 NTP 详解

## 文章导读
时间同步是 Linux 系统稳定运行的基础。本文从 **Linux 的两个时钟（硬件时钟 RTC 与系统时钟）** 讲起，讲解 **date/timedatectl 设置时间**、**NTP 网络时间协议原理**、**chrony 的安装与配置**、常用**授时中心**，并通过**同步时间**与**搭建本地时间同步服务器**两个实验实战，最后介绍 chronyc 命令与常见时区，适合需要掌握 Linux 时间管理的运维学习者。

## 一、Linux 的两个时钟

### 1. 硬件时钟 RTC（Real Time Clock）
即 BIOS 时钟，也就是主板中用电池供电的时钟，将时间写入 BIOS 中，系统断电后时间不会丢失，可在开机时通过主板程序进行设置。

```bash
# 查看硬件时间
[root@server ~]# hwclock
2023-05-30 09:48:32.535594+08:00
```

### 2. 系统时钟（System Clock）
即 Linux 系统内核时钟、软件时钟，由 Linux 内核提供。系统时钟基于内存，**如果系统断电时间就会丢失**。

```bash
# 查看系统时间
[root@server ~]# date
2023年 05月 30日 星期二 09:50:50 CST

[root@server ~]# date -s 10:00    # 修改为错误的时间
2023年 05月 30日 星期二 10:00:00 CST
[root@server ~]# date
2023年 05月 30日 星期二 10:00:01 CST
[root@server ~]# hwclock -s        # 向硬件时间同步
[root@server ~]# date
2023年 05月 30日 星期二 09:51:50 CST
```

## 二、设置日期时间

### 1. timedatectl 命令设置
```bash
[root@server ~]# timedatectl    # 显示当前的日期和时间
       Local time: 三 2023-11-15 13:00:26 CST       # 本地时间
    Universal time: 三 2023-11-15 05:00:26 UTC      # 世界时间
          RTC time: 三 2023-11-15 06:16:16            # 硬件时间
         Time zone: Asia/Shanghai (CST, +0800)      # 时区
System clock synchronized: yes                         # 时间是否已同步
          NTP service: active                          # 时间同步服务已启动
       RTC in local TZ: no                             # no 表示硬件时钟设置为协调世界时（UTC），yes 表示设置为本地时间
```

```bash
[root@server ~]# systemctl status chronyd   # 查看时间同步服务状态（默认使用 chrony 同步，不再使用 ntp 服务）

[root@server ~]# timedatectl set-ntp no   # 关闭时间同步，方便修改日期时间

[root@server ~]# timedatectl set-time "2023-12-12"   # 设置新日期

[root@server ~]# timedatectl set-time "12:12:12"    # 设置时间

[root@server ~]# timedatectl
       Local time: 二 2023-12-12 12:12:22 CST
    Universal time: 二 2023-12-12 04:12:22 UTC
          RTC time: 二 2023-12-12 04:12:23
         Time zone: Asia/Shanghai (CST, +0800)
System clock synchronized: no
          NTP service: inactive
       RTC in local TZ: no

[root@server ~]# timedatectl list-timezones | grep Asia   # 查看可用时区
[root@server ~]# timedatectl set-timezone Asia/Shanghai   # 设置时区
```

## 三、NTP（Network Time Protocol）

**NTP**（Network Time Protocol，网络时间协议）是由 RFC 1305 定义的时间同步协议，用来在分布式时间服务器和客户端之间进行时间同步。

- **基于 UDP 报文传输，使用的 UDP 端口号为 123**
- NTP 可以对网络内所有具有时钟的设备进行时钟同步，使网络内所有设备的时钟保持一致，从而提供基于统一时间的多种应用
- 运行 NTP 的本地系统，既可以接受来自其他时钟源的同步，又可以作为时钟源同步其他时钟，并可与其他设备互相同步
- **精度**：局域网内可达 0.1ms，互联网上绝大多数地方可达 1-50ms

**时间来源与 Stratum（层）**
NTP 提供准确时间，首先要有准确的时间来源，这一时间应该是国际标准时间 UTC。NTP 获得 UTC 的时间来源可以是原子钟、天文台、卫星，也可以从 Internet 上获取。时间按 NTP 服务器的等级传播，按照离外部 UTC 源的远近将所有服务器归入不同的 **Stratum（层）**：
- **Stratum-1** 在顶层，有外部 UTC 接入
- **Stratum-2** 从 Stratum-1 获取时间，**Stratum-3** 从 Stratum-2 获取时间，以此类推
- Stratum 层的总数限制在 **15 以内**，所有服务器在逻辑上形成阶梯式架构相互连接，Stratum-1 的时间服务器是整个系统的基础

> 计算机主机一般同多个时间服务器连接，利用统计学算法过滤来自不同服务器的时间，以选择最佳路径和来源校正主机时间。即使主机长时间无法与某一时间服务器联系，NTP 服务依然有效运转。为防止对时间服务器的恶意破坏，NTP 使用**识别（Authentication）机制**，检查对时信息是否真正来自所宣称的服务器并检查资料返回路径，提供抗干扰保护。

## 四、Chrony

**chrony** 是一个开源自由软件，能帮助你保持系统时钟与时钟服务器（NTP）同步，让时间保持精确。它由两个程序组成：

| 程序 | 说明 |
|---|---|
| `chronyd` | 后台运行的守护进程，用于调整内核中运行的系统时钟与时钟服务器同步，确定计算机增减时间的比率并对此进行补偿 |
| `chronyc` | 提供用户界面，用于监控性能并进行多样化配置，可在 chronyd 控制的本机或远程计算机上工作 |

> **注意**：Chrony 与 NTP 都是时间同步软件，**两个软件不能同时开启**，会出现时间冲突。openEuler 和 RHEL 中默认使用 chrony 作为时间服务器，不再支持 NTP 软件包。

### 1. 安装
默认已安装，若需要安装可执行：
```bash
[root@server ~]# yum install chrony -y
[root@server ~]# systemctl start chronyd
[root@server ~]# systemctl enable chronyd
```

### 2. Chrony 配置文件分析
主配置文件：`/etc/chrony.conf`

```conf
# 使用 pool.ntp.org 项目中的公共服务器，或使用 server 开头的服务器，理论上想添加多少时间服务器都可以
# iburst 表示首次同步时快速同步
pool pool.ntp.org iburst

# 根据实际时间计算服务器增减时间的比率，记录到文件中，系统重启后为系统做最佳时间补偿调整
driftfile /var/lib/chrony/drift

# 如果系统时钟的偏移量大于 1 秒，则允许系统时钟在前三次更新中步进
makestep 1.0 3

# 启用实时时钟（RTC）的内核同步
rtcsync

# 通过 hwtimestamp 指令启用硬件时间戳（默认注释）
#hwtimestamp *

# 指定 NTP 客户端地址，以允许或拒绝连接到扮演时钟服务器的机器（默认注释）
#allow 192.168.48.0/24

# 即使未同步到时间源也提供时间（默认注释）
# local stratum 10

# 指定包含 NTP 身份验证密钥的文件（默认注释）
# keyfile /etc/chrony.keys

# 指定日志文件的目录
logdir /var/log/chrony
```

## 五、实验

### 实验一：同步时间

**第一步：先修改成错误时间**
```bash
[root@server ~]# date -s 10:30
2023年 05月 30日 星期二 10:30:00 CST
```

**第二步：编制 chrony 的配置文件**
```bash
[root@server ~]# vim /etc/chrony.conf
# 定位第 3 行，删除后添加阿里的时间同步服务地址
server ntp.aliyun.com iburst
```
> 注意：也可以先清空 chrony.conf 内容，将阿里开源提供的时间服务器推荐配置复制粘贴到该文件中。

**第三步：重启服务、时间同步**
```bash
[root@server ~]# systemctl restart chronyd
[root@server ~]# chronyc sources -v
```

**第四步：查看时间是否同步**
```bash
[root@server ~]# timedatectl status
```

### 实验二：搭建本地时间同步服务器

**架构**

| 性质 | IP 地址 | 同步对象 |
|---|---|---|
| 服务端 server | 192.168.60.128 | ntp.aliyun.com |
| 客户端 node1 | 192.168.60.131 | 192.168.60.128 |

要求：服务端 server 向阿里时间服务器同步；客户端 node1 向服务端 server 同步。

**第一步：定位服务端 server**
```bash
# 安装软件
[root@server ~]# yum install chrony -y    # 默认已安装

# 编辑配置文件，定位第 3 行，修改为阿里的时间服务地址
[root@server ~]# vim /etc/chrony.conf
server ntp.aliyun.com iburst

# 重启服务
[root@server ~]# systemctl restart chronyd

# 测试
[root@server ~]# chronyc sources -v
[root@server ~]# timedatectl status

# 设置允许客户端时间同步
[root@server ~]# vim /etc/chrony.conf
allow 192.168.60.131/24    # 设置谁可以访问本机进行同步
[root@server ~]# systemctl restart chronyd
```

**第二步：定位客户端 node1**
```bash
[root@node1 ~]# yum install chrony -y

# 编辑配置文件，修改第 3 行为 server 的地址
[root@node1 ~]# vim /etc/chrony.conf
server 192.168.60.128 iburst

# 重启服务
[root@node1 ~]# systemctl restart chronyd

# 测试
[root@node1 ~]# chronyc sources -v
^* 192.168.60.128          3   6    17    39    +20us[ +252us] +/-   38ms

[root@node1 ~]# timedatectl status
       Local time: 二 2023-05-30 11:08:37 CST
    Universal time: 二 2023-05-30 03:08:37 UTC
          RTC time: 二 2023-05-30 03:08:38
         Time zone: Asia/Shanghai (CST, +0800)
System clock synchronized: yes
          NTP service: active
       RTC in local TZ: no
```

> **客户端同步失败的原因**：检查网络连通性（需要能 ping 通）；检查服务端的 `allow` 参数；需要重启服务；需要关闭服务端防火墙：`systemctl disable firewalld`。

## 六、chronyc 命令

**查看时间服务器**
```bash
[root@server ~]# chronyc sources -v    # -v 参数表示显示内容是否有解释
MS Name/IP address         Stratum Poll Reach LastRx Last sample
======================================================================
```

**chronyc sources 输出分析**

| 列 | 含义 |
|---|---|
| 第一列（M） | 信号源模式。`^` 表示服务器，`=` 表示对等方，`#` 表示本地连接的参考时钟 |
| 第二列（S） | 源的状态：`*` 为当前同步到的源；`+` 为可接受并组合的源；`-` 为被合并算法排除的可接受源；`?` 为失去连接的源；`x` 为虚假时钟（时间与大多数其他来源不一致）；`~` 为时间可变性过大的源 |
| Name/IP address | 服务器源的名称或 IP 地址 |
| Stratum | 源的层级。层级 1 表示本地连接的参考时钟，第 2 层表示通过第 1 层计算机的时钟同步，依此类推 |
| Poll | 源轮询频率，以秒为单位，值是基数 2 的对数，如值 6 表示每 64 秒测量一次，chronyd 会根据情况自动改变轮询频率 |
| Reach | 源可达性的锁存值（八进制），有 8 位，接收或丢失一次更新一位，值 377 表示最后八次传输都收到有效回复 |
| LastRx | 从源收到最近一次的时间，通常为几秒，字母 m、h、d、y 分别表示分钟、小时、天、年 |
| Last sample | 本地时钟与上次测量时源的偏移量。方括号左侧为原始测量值，右侧为偏差值，`+/-` 后的数字为误差范围。正偏移表示本地时钟位于源时钟之前 |

## 七、常见时区

- **UTC**：整个地球分为二十四时区，每个时区都有自己的本地时间。在国际无线电通信场合，为统一起见使用统一时间，称为**通用协调时（UTC，Universal Time Coordinated）**。
- **GMT**：格林威治标准时间（Greenwich Mean Time），指位于英国伦敦郊区的格林尼治天文台的标准时间，因为本初子午线定义在通过那里的经线（UTC 与 GMT 时间基本相同，本文不做区分）。
- **CST**：中国标准时间（China Standard Time），GMT + 8 = UTC + 8 = CST。
- **DST**：夏令时（Daylight Saving Time），指在夏天太阳升起较早时，将时间拨快一小时以提早日光使用（**中国不使用**）。

## 八、小结
Linux 时间管理的核心是区分**硬件时钟（RTC）**与**系统时钟**，通过 `date`、`timedatectl` 设置时间，借助 **chrony** 完成与授时中心的同步，并可搭建本地时间服务器为内网主机授时。掌握 NTP 的 Stratum 层级、chrony 配置项与 `chronyc sources` 输出分析，是排查时间同步问题的关键。
